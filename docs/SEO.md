> 이 문서는 그 가이드를 **이 코드베이스 기준으로 실행 가능하게 쪼갠 것**입니다.
> 최종 갱신: 2026-07-28

## 현재 색인 상태 — 실측 (2026-07-27, 구글 한국 `hl=ko&gl=kr`)

> ⚠️ **미국 기준 검색 도구로는 이 결과가 안 보입니다.** 한 번 그것만 보고
> "인덱스 0건" 이라고 잘못 판정한 적이 있습니다. 반드시 `hl=ko&gl=kr` 로 확인하세요.

| 검사 | 결과 |
|---|---|
| `https://susannadesign.co.kr/` | ✅ 200 · 112KB · 1.5s |
| Googlebot·GPTBot·OAI-SearchBot·ChatGPT-User·PerplexityBot·ClaudeBot·Yeti·bingbot | ✅ **8종 전부 200** — 차단 0건 |
| `robots.txt` · `<meta robots>` · canonical · title · description · JSON-LD · sitemap | ✅ 전부 정상 |
| **"수산나디자인" 검색** | ✅ **자사 홈페이지가 1위** — 우리가 넣은 타이틀·설명 그대로 |
| **`site:susannadesign.co.kr`** | ⚠️ **홈 1페이지뿐** — 나머지 9개 주소 미색인 |
| **AI 개요(제미나이)가 인용하는 출처** | 🔴 잡코리아 · RnDcircle · 인스타그램 · 비즈노 — **자사 홈페이지 없음** |

기술적으로 막힌 곳은 없습니다. 남은 문제는 두 가지입니다.

### ⚠️ 문제 1 — 홈 말고는 색인이 안 됐습니다

사이트맵에 10개가 있는데 1개만 들어갔습니다. Search Console 에서
**Sitemaps → `sitemap.xml` 제출**이 됐는지 확인하고, **URL 검사 → 색인 생성 요청**을
`/works` `/about` `/signs` 정도에 걸어 주세요 (C4 상세 참조).

### 🔴 문제 2 — AI 가 자사 홈페이지 대신 채용·기업정보 사이트를 인용합니다

제미나이·구글 AI 개요가 회사를 **알고는 있는데**, 근거로 잡코리아·RnDcircle·
비즈노·인스타그램을 답니다.

**차단 문제가 아닙니다.** 크롤러 8종이 전부 200 으로 통과하는 것을 실측했습니다.
**AI 인용은 "차단을 푸는 문제"가 아니라 "인용할 사실을 주는 문제"입니다.**

| 남은 원인 | 무엇이 필요한가 |
|---|---|
| **색인된 지 며칠 안 됨** | AI 개요의 근거 자료는 색인보다 **몇 주** 늦게 갱신됩니다 — 기다리는 것 외엔 없습니다 |
| **디렉터리가 더 많은 사실을 갖고 있음** | 설립연도·대표자·사업자번호 같은 정형 사실은 이제 우리도 구조화 데이터로 냅니다(`taxID`·`sameAs`·`WebSite`). 남은 건 **사진 50자리** 와 **시공사례 상세** 입니다 |

> 엔티티 신호(`sameAs`·`taxID`·`WebSite`)는 AI 가 "이 홈페이지 = 그 회사" 로
> **식별**하게 합니다. 하지만 인용할 **내용**을 만드는 건 사진과 시공사례입니다.

### 네이버 URL 검사 느낌표 — 처리 결과 (2026-07-28)

소유확인 직후 URL 검사에서 느낌표 3건이 떴고, 파는 과정에서 2건을 더 찾았습니다.

| # | 항목 | 진단 | 처리 |
|---|---|---|---|
| 1 | 페이지 설명 80자 초과 | 전 페이지 89~107자 | ✅ **43~62자**로 재작성 |
| 2 | OG 설명 80자 초과 | 96자 | ✅ 위와 같은 값으로 통일 |
| 3 | `robots.txt` 없음 | ❌ **오탐** — Yeti UA 로 실측 시 `200 / text/plain / 500B`, 내용 정상, Yeti 차단 없음 | 코드 문제 아님. **배포 후 URL 검사 재실행**해서 그때도 뜨면 다시 팝니다 |
| 4 | **OG 설명이 전 페이지 동일** | 각 `page.tsx` 가 `description` 만 적고 `og:description` 은 아무도 안 적어 **10개 페이지가 전부 홈 설명을 공유**. 어느 페이지를 카톡에 붙여도 홈 소개가 떴습니다 | ✅ `lib/seo.ts` `pageMetadata()` 로 통합 |
| 5 | **사이트맵에 `noindex` 3개** | `/privacy` `/terms` `/no-email-collect` 를 제출하면서 동시에 `noindex` → **모순 신호**. 제출 10건 중 3건이 영구 실패로 남습니다 | ✅ 사이트맵 **7건**으로 축소 |

4·5번은 운영 사이트에서 실제로 재현해 확인한 뒤 고쳤습니다.

> ⚠️ **4번을 고칠 때의 함정** — Next.js 는 메타데이터를 **얕게 병합**합니다.
> 페이지에서 `openGraph` 를 **한 필드라도** 적으면 `layout.tsx` 의 `openGraph` 가
> 통째로 교체돼 **`og:image` 가 조용히 사라집니다.** 화면엔 아무 표시도 안 납니다.
> 그래서 `pageMetadata()` 가 매번 `openGraph` 전체를 다시 채웁니다 —
> 페이지에서 직접 `openGraph` 를 적지 마세요. (근거: `node_modules` 의
> `generate-metadata.md` §Merging)

## 요약: 홈페이지로 할 수 있는 일은 전체의 절반뿐입니다

가이드의 핵심은 네이버와 구글의 메커니즘이 다르다는 것입니다.

| | 홈페이지 기여도 | 나머지 |
|---|---|---|
| **구글** | 8할 — 코드 품질·구조화 데이터가 직접 순위 | GBP 2할 |
| **네이버** | 2할 — 서치어드바이저 색인 정도 | 플레이스·블로그 8할 |

즉 **코드를 아무리 잘 짜도 네이버 노출은 거의 안 움직입니다.** 네이버는 플레이스 등록과
블로그 운영이 실체이고, 그건 사람이 해야 합니다. 아래 C 섹션이 그 목록입니다.

## A. 코드에 적용 완료 (2026-07-24)

### A-1. 온페이지 — 지역 키워드 배치

가장 큰 구멍이었습니다. 기존 타이틀이 `회사소개 | 수산나디자인` 형태라
**"대전 간판"으로 검색하면 잡힐 근거가 아예 없었습니다.**

**메타 설명**: 홈이 361자라 검색결과에서 잘리고 있었습니다 → 재작성.

> ⚠️ **80자가 상한입니다.** 처음엔 "한글은 90~110자" 로 잡아 전 페이지를 89~107자로
> 맞췄는데, **네이버 서치어드바이저 URL 검사가 느낌표를 냈습니다**(2026-07-28, 96자).
> 가이드의 "150~160자" 는 영문 기준이고 한글 한계선은 그보다 훨씬 낮습니다.
> → 전 페이지 **43~62자**로 다시 줄였습니다. 값은 `config/site.ts` 의
> `seo.homeDescription` 과 `seo.pages` 에 모여 있습니다 [A5].

**키워드**: `config/site.ts` 의 `seo.primary` 로 이전. 지역 × 서비스 × 의도 3레이어 중
**실제로 하는 일만** 골랐습니다. 하지 않는 서비스를 키워드로 넣으면 들어온 사람이
바로 이탈해 오히려 순위에 해롭습니다.

## B. 코드로 가능하지만 **콘텐츠가 먼저** 필요한 것

### B-1. 시공사례 개별 페이지 ★ 가장 효과가 큼

가이드 §3.6: *"시공사례 페이지는 로컬 SEO에서 가장 강력한 콘텐츠 자산."*
각 사례를 별도 URL로 발행하면 `대전 유성구 카페 채널간판 시공` 같은 롱테일을 자동으로 덮습니다.

**아직 만들지 않았습니다.** 지금 데이터로 상세 페이지를 만들면 제목·업종·사진 한 장뿐이라
가이드 §3.7이 경고한 **"얇은 콘텐츠"** 가 되어 오히려 페널티 대상이 됩니다.
2026년 상반기 코어 업데이트에서 이 패턴이 강하게 처벌받았습니다.

필요한 것 — 사례당:
- 시공 위치(구/동 단위) · 간판 종류 · 시공 기간 · 사용 자재 · 시공 전후 사진
- 현장에서 겪은 구체적 내용 3~4문장 (벽면 재질, 고소작업 여부 등)

이 필드를 DB에 추가하고 관리자 화면에서 채울 수 있게 하는 건 준비되면 바로 가능합니다.
**최소 3~5건이라도 제대로 채운 뒤 발행**하는 편이 15건을 얇게 까는 것보다 낫습니다.

### B-2. 지역별 페이지
`/대전-서구-간판` 식 페이지는 **지명만 바꾼 템플릿이면 확실히 페널티**입니다(§3.7).
해당 구의 실제 시공사례가 3건 이상 쌓인 뒤에만 만듭니다. 지금은 하지 않는 게 맞습니다.

### B-3. 정보성 콘텐츠
`옥외광고물 허가 절차`, `대전 강풍 대비 간판 시공 시 주의점` 같은 글.
E-E-A-T의 "경험" 축을 채우는 항목이라 업계 일반론 복사는 역효과입니다.

### C4 상세 — Google Search Console (★ 이거 하나면 구글 문제가 풀립니다)

**5분입니다.** 지금 구글에 사이트가 안 나오는 유일한 이유가 이 단계를 안 해서입니다.

**1) 등록** — [search.google.com/search-console](https://search.google.com/search-console)
접속 → 구글 계정 로그인 → 왼쪽 위 **속성 추가**

**2) 방식 선택 — 왼쪽 "도메인"을 고르세요**

| | 소유확인 방법 | 재배포 | 권장 |
|---|---|---|---|
| **도메인** | Cloudflare DNS 에 **TXT 레코드** 1줄 추가 | **불필요** | ★ 이쪽 |
| URL 접두어 | HTML 태그 코드를 코드에 넣고 배포 | 필요 | 차선 |

`susannadesign.co.kr` 을 입력하면 구글이 `google-site-verification=...` 로 시작하는
TXT 값을 줍니다. 도메인을 이미 Cloudflare 에서 관리하시니 붙여넣기로 끝납니다.

**3) TXT 넣기** — [dash.cloudflare.com](https://dash.cloudflare.com) → `susannadesign.co.kr`
→ **DNS** → **Record 추가**

| 항목 | 값 |
|---|---|
| Type | `TXT` |
| Name | `@` (도메인 루트 그대로) |
| Content | 구글이 준 `google-site-verification=...` 전체 |
| Proxy | TXT 는 프록시 설정이 없습니다 |

저장 후 Search Console 로 돌아가 **확인**. 보통 1~2분, 늦어도 한 시간입니다.

**4) 사이트맵 제출** — Search Console 왼쪽 **Sitemaps** →
`sitemap.xml` 입력 → **제출**. "성공"이 뜨면 됩니다.

```
https://susannadesign.co.kr/sitemap.xml
```

**5) 색인 요청 ★ 이게 실제로 순위를 당깁니다** — 맨 위 검색창(**URL 검사**)에
아래를 넣고 → **색인 생성 요청**. 이러면 구글이 며칠 안에 직접 찾아옵니다.


### AI 답변 엔진 인용 — 크롤러는 이미 열려 있습니다

**목표**: "대전 간판업체 추천해줘" 같은 질문에 ChatGPT·Perplexity·구글 AI 개요가
이 사이트를 인용하게 하는 것.

접근 자체는 **두 겹으로 열려 있습니다.** Cloudflare 관리형 `robots.txt` 블록이
해제됐고, `app/robots.ts` 가 AI 크롤러 14종을 이름으로 지목해 `Allow` 를 선언합니다
(F15). 실측상 AI 봇에 걸린 `Disallow: /` 가 하나도 없고 UA 8종이 전부 200 입니다.

> ⚠️ **`app/robots.ts` 를 고칠 때** — AI 그룹에도 `/api/` `/admin` 차단이 반드시
> 같이 들어 있어야 합니다. 크롤러는 자기 이름의 그룹이 있으면 `*` 그룹을 아예
> 보지 않으므로, 빼먹으면 **이 봇들에게만 관리자 화면이 열립니다.** `POLICY` 를
> 두 그룹이 공유하는 구조가 그래서 중요합니다 — 한쪽만 고치지 마세요.

> **Cloudflare 가 기본값을 다시 켜더라도** 한 겹 버팁니다. robots.txt 는 같은
> User-agent 그룹끼리 합쳐지고, 동일 구체성의 Allow/Disallow 충돌 시 Allow 가
> 이깁니다(RFC 9309 · 구글 문서).

**알고 계실 트레이드오프**: 같은 봇들이 콘텐츠를 **AI 학습에도** 씁니다
(`GPTBot` `Google-Extended` `Applebot-Extended` 등). 이 사이트는 회사 소개·시공실적
이라 학습에 쓰여도 잃을 게 거의 없고 인용 유입이 더 큰 이득입니다. 생각이 바뀌면
Cloudflare 대시보드 → **AI Crawl Control** 에서 되돌리고, 그때 `app/robots.ts` 의
`AI_CRAWLERS` 배열도 함께 비웁니다.

**그래서 지금 부족한 건 접근이 아니라 콘텐츠입니다** — 위 "문제 2" 참조.
