# 검색 상위노출 — 가이드 적용 현황

> 출처: [`대전_간판업체_네이버구글_상위노출_가이드.md`](../대전_간판업체_네이버구글_상위노출_가이드.md)
> 이 문서는 그 가이드를 **이 코드베이스 기준으로 실행 가능하게 쪼갠 것**입니다.
> 최종 갱신: 2026-07-24

## 요약: 홈페이지로 할 수 있는 일은 전체의 절반뿐입니다

가이드의 핵심은 네이버와 구글의 메커니즘이 다르다는 것입니다.

| | 홈페이지 기여도 | 나머지 |
|---|---|---|
| **구글** | 8할 — 코드 품질·구조화 데이터가 직접 순위 | GBP 2할 |
| **네이버** | 2할 — 서치어드바이저 색인 정도 | 플레이스·블로그 8할 |

즉 **코드를 아무리 잘 짜도 네이버 노출은 거의 안 움직입니다.** 네이버는 플레이스 등록과
블로그 운영이 실체이고, 그건 사람이 해야 합니다. 아래 C 섹션이 그 목록입니다.

## A. 코드에 적용 완료 (2026-07-24)

### A-1. 온페이지 — 지역 키워드 배치

가장 큰 구멍이었습니다. 기존 타이틀이 `회사소개 | 수산나디자인` 형태라
**"대전 간판"으로 검색하면 잡힐 근거가 아예 없었습니다.**

| 페이지 | 이전 | 이후 | 자수 |
|---|---|---|---|
| `/` | 수산나디자인 \| 옥내외광고물 · 간판디자인 · 철구조물 전문업체 | **대전 간판제작·옥외광고물 전문** \| 수산나디자인 | 25 |
| `/about` | 회사소개 | **대전 간판업체** 회사소개 | 21 |
| `/signs` | 사업영역 | **대전 간판·옥외광고물** 사업영역 | 25 |
| `/works` | 주요실적 | **대전 간판 시공사례** | 19 |
| `/process` | 업무프로세스 | **간판 제작·시공** 업무프로세스 | 24 |
| `/quote` | 무료 견적 문의 | **대전 간판** 무료 견적 문의 | 23 |
| `/support` | 고객지원 | 고객지원 · 자주 묻는 질문 | 24 |

전부 60자 이내(가이드 기준)이며 키워드가 앞쪽에 있습니다.

**메타 설명**: 홈이 361자라 검색결과에서 잘리고 있었습니다 → **96자**로 재작성.
전 페이지 89~107자로 정리했습니다.
가이드의 "150~160자"는 영문 기준이고, 한글은 90~110자가 잘리지 않는 실제 한계선입니다.

**키워드**: `config/site.ts` 의 `seo.primary` 로 이전. 지역 × 서비스 × 의도 3레이어 중
**실제로 하는 일만** 골랐습니다. 하지 않는 서비스를 키워드로 넣으면 들어온 사람이
바로 이탈해 오히려 순위에 해롭습니다.

### A-2. 구조화 데이터

| 스키마 | 위치 | 상태 |
|---|---|---|
| `LocalBusiness` | 전 페이지 (`app/layout.tsx`) | 대폭 보강 |
| `FAQPage` | `/support` | **신규** — 질문 8개 |
| `BreadcrumbList` | 서브 페이지 9개 | **신규** |

**고친 버그**: 기존 `openingHours: "Mo-Su 08:00-19:00"` 이 실제 정보
(`평일 09:00~18:00 / 주말·공휴일 휴무`)와 **어긋나 있었습니다.**
가이드가 반복해 경고하는 NAP 불일치이고, AI 요약이 틀린 영업시간을 인용하게 됩니다.
→ `openingHoursSpecification` 으로 교체해 `config/site.ts` 와 일치시켰습니다.

**추가한 것**: `geo`(좌표 — 로컬팩의 "거리" 요인), `areaServed`(출장 시공 지역 9곳),
`image` · `logo` · `founder` · `foundingDate` · `sameAs` · `addressRegion`.

**일부러 넣지 않은 것**: `AggregateRating` · `Review`.
자사 사이트에 실제 게시된 리뷰에만 쓸 수 있고, 플레이스·GBP 리뷰를 긁어 넣으면
**리치 결과 제외 또는 수동 조치** 대상입니다 (가이드 §3.3, §6).

## B. 코드로 가능하지만 **콘텐츠가 먼저** 필요한 것

### B-1. 시공사례 개별 페이지 ★ 가장 효과가 큼

가이드 §3.6: *"시공사례 페이지는 로컬 SEO에서 가장 강력한 콘텐츠 자산."*
각 사례를 별도 URL로 발행하면 `대전 유성구 카페 채널간판 시공` 같은 롱테일을 자동으로 덮습니다.

**아직 만들지 않았습니다.** 지금 데이터로 상세 페이지를 만들면 제목·업종·사진 한 장뿐이라
가이드 §3.7이 경고한 **"얇은 콘텐츠"** 가 되어 오히려 페널티 대상이 됩니다.
2026년 상반기 코어 업데이트에서 이 패턴이 강하게 처벌받았습니다.

필요한 것 — 사례당:
- 시공 위치(구/동 단위) · 간판 종류 · 시공 기간 · 사용 자재 · 시공 전후 사진
- 현장에서 겪은 구체적 내용 3~4문장 (벽면 재질, 고소작업 여부 등)

이 필드를 DB에 추가하고 관리자 화면에서 채울 수 있게 하는 건 준비되면 바로 가능합니다.
**최소 3~5건이라도 제대로 채운 뒤 발행**하는 편이 15건을 얇게 까는 것보다 낫습니다.

### B-2. 지역별 페이지
`/대전-서구-간판` 식 페이지는 **지명만 바꾼 템플릿이면 확실히 페널티**입니다(§3.7).
해당 구의 실제 시공사례가 3건 이상 쌓인 뒤에만 만듭니다. 지금은 하지 않는 게 맞습니다.

### B-3. 정보성 콘텐츠
`옥외광고물 허가 절차`, `대전 강풍 대비 간판 시공 시 주의점` 같은 글.
E-E-A-T의 "경험" 축을 채우는 항목이라 업계 일반론 복사는 역효과입니다.

### AI 답변 엔진 인용 — ✅ 열렸습니다 (2026-07-26)

**목표**: "대전 간판업체 추천해줘" 같은 질문에 ChatGPT·Perplexity·구글 AI 개요가
이 사이트를 인용하게 하는 것.

**막혀 있던 원인**: Cloudflare 가 우리 `app/robots.ts` 결과 **앞에** 관리형 블록을
끼워 넣고 `GPTBot` `ClaudeBot` `Google-Extended` `CCBot` 등을 `Disallow: /` 로
막고 있었습니다. **신규 도메인 기본값**이라 대표님이 켠 게 아니었습니다.
(WAF 실차단은 아니었습니다 — AI 봇 UA 로 접근하면 200 이 떨어졌습니다.)

**현재 상태 — 실측 확인**

```
$ curl https://susannadesign.co.kr/robots.txt      # 24줄, Cloudflare 블록 0건
User-Agent: *                    Allow: /  Disallow: /api/  /admin
User-Agent: GPTBot … CCBot(14종)  Allow: /  Disallow: /api/  /admin
Sitemap: https://susannadesign.co.kr/sitemap.xml
```

AI 봇에 걸린 `Disallow: /` 가 **하나도 없습니다.** 3회 반복 확인했습니다.

**두 겹으로 되어 있습니다**

1. **Cloudflare 관리형 `robots.txt` 해제** — 관리형 블록이 응답에서 사라졌습니다

### 도메인 — `www` 301 이 아직 안 걸려 있습니다

`site.url = https://susannadesign.co.kr` (**www 없음**)으로 확정했습니다.
sitemap · RSS · 구조화 데이터 · canonical · OG 가 전부 이 값에서 나옵니다.

**www 를 이쪽으로 301 리다이렉트해야 합니다.** `www.susannadesign.co.kr` 과
`susannadesign.co.kr` 이 둘 다 열리면 검색엔진이 서로 다른 사이트로 보고
평가가 반으로 쪼개집니다(중복 콘텐츠). 호스팅/DNS 설정 사안이라 코드로는 못 막습니다.

| 배포처 | 방법 |
|---|---|
| **Cloudflare** (현재 배포처) | Rules → Redirect Rules 에 301 규칙 추가. 화면 그대로 따라가는 절차는 [`DEPLOY.md`](DEPLOY.md) **5-3** 에 있습니다 |
| Vercel | Domains 에 둘 다 등록 → `susannadesign.co.kr` 을 Primary 로 지정하면 www 가 자동 301 |
| 그 외 | 웹서버(nginx 등)에서 `www.` → 비 www 301 규칙 추가 |

C1~C5 채널 등록 시 홈페이지 주소도 **www 없는 형태**로 통일해 적으세요.
